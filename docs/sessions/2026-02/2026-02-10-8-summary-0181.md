## 2. Análisis del Problema de Roles

### 2.1 Investigación

Se rastreó el flujo completo de creación de usuarios:

```
dev_users.json (scripts/secrets/users_with_passwords/)
       │
       │ Contiene: {name, surname, email, password}
       │ Password prefix indica rol: adm=ADMIN, mng=MANAGER, usr=USER
       ▼
seed_runner.py (scripts/seeds/)
       │
       │ Usa endpoint: POST /api/v1/auth/signup
       │ Solo envía: {name, surname, email, password}
       ▼
AuthController.signup()
       │
       │ SIEMPRE asigna rol USER por defecto
       │ Línea 79 de UserServiceImpl.java:
       │   roleDao.findByName(ROLE_USER)
       ▼
Base de datos
       │
       └── TODOS los usuarios = ROLE_USER ❌
```

### 2.2 Causa Raíz

El endpoint `/api/v1/auth/signup` **siempre** asigna `ROLE_USER` por defecto. El seeder no tenía lógica para:
1. Detectar el rol intencionado del prefijo de contraseña
2. Actualizar el rol después de crear el usuario

### 2.3 Archivos Analizados

| Archivo | Propósito | Hallazgo |
|---------|-----------|----------|
| `sql/common/03_roles.sql` | Crea roles | Solo INSERT de ADMIN, USER, MANAGER |
| `sql/common/05_admin_bootstrap_dev_test.sql` | Bootstrap admins | Solo Ada y Alan como ADMIN |
| `UserServiceImpl.java:79` | Asigna rol default | Siempre ROLE_USER |
| `AuthController.java:76-89` | Endpoint signup | No acepta roleIds |
| `UserControllerImpl.java:107-115` | PUT user | Sí permite actualizar roles |

### 3.1 Modificaciones a seed_runner.py

#### Método 1: `_get_role_from_password_prefix()`

```python
def _get_role_from_password_prefix(self, password: str) -> tuple:
    """Determine role ID and name from password prefix.
    
    Password prefixes indicate intended roles:
    - 'adm' = ADMIN (roleId=1)
    - 'mng' = MANAGER (roleId=3)
    - 'usr' = USER (roleId=2)
    
    Returns: (role_id, role_name)
    """
    if not password:
        return (2, "USER")
    
    prefix = password[:3].lower()
    if prefix == "adm":
        return (1, "ADMIN")
    elif prefix == "mng":
        return (3, "MANAGER")
    else:
        return (2, "USER")
```

## 4. Fix del Tamaño de Fuente iOS

### 4.1 Problema

Safari en iOS hace auto-zoom cuando el usuario enfoca un input con fuente menor a 16px.

### 4.2 Solución

Añadir clase `text-base` (16px) al componente `Input.jsx`:

```jsx
// Antes
className={`... text-sm ...`}

// Después
className={`... text-sm text-base ...`}
```

**Nota**: `text-base` sobrescribe `text-sm` garantizando 16px mínimo.

Es un **falso positivo** de una extensión de VS Code que valida versiones npm. La extensión tiene caché desactualizado o usa un registry diferente.

## 10. Lecciones Aprendidas

### 10.1 Arquitectura

1. **Endpoints de signup** típicamente asignan rol default por seguridad
2. **Seed data** debe manejar roles explícitamente, no depender de defaults
3. **API responses** pueden tener nombres de campos diferentes al modelo (`roleDtos` vs `roles`)

### 10.2 Debugging

1. **Prefijos de contraseña** son convención útil para identificar roles sin exponer datos
2. **Verificar siempre** que los datos en DB coinciden con expectativas
3. **Warnings de IDE** no siempre indican errores reales

### 10.3 iOS Compatibility

1. Safari auto-zoom en inputs < 16px es comportamiento conocido
2. Tailwind `text-base` (16px) es la solución estándar
