## 2. Correcciones de Bugs en Backend

### 2.1 Bug: Duplicación de Nóminas al Editar

**Problema**: Al editar una nómina existente, se creaba un nuevo registro en lugar de actualizar el existente.

**Causa Raíz**: El método `update()` en `PayrollServiceImpl` no asignaba el ID de la URL al objeto payroll antes de guardar. JPA interpretaba el objeto sin ID como nueva entidad.

**Archivo Modificado**: `backend/src/main/java/io/sunbit/app/service/PayrollServiceImpl.java`

**Solución**:
```java
@Override
@Transactional
public Payroll update(Long id, Payroll payroll, String headerAuth) throws Exception {
    Payroll payrollUpdated = null;
    try {
        Optional<Payroll> optionalPayroll = payrollDao.findById(id);
        if (optionalPayroll.isEmpty()) {
            throw new ResourceNotFoundException("Payroll", "id", id);
        }
        // IMPORTANTE: Usar el ID de la URL, no del body
        payroll.setId(id);
        syncAssociations(payroll);
        LocalDateTime parsedDate = DateUtil.formattingDate(payroll.getPayrollDate());
        payroll.setPayrollDate(parsedDate);
        payrollUpdated = payrollDao.save(payroll);
    } catch (BadRequestException | ResourceNotFoundException e) {
        throw e;
    } catch (Exception e) {
        e.printStackTrace();
        throw new Exception(e.getMessage());
    }
    return payrollUpdated;
}
```

**Cambios Clave**:
- Verificación con `isEmpty()` en lugar de `get()` seguido de null check
- Línea agregada: `payroll.setId(id)` antes de save
- Propagación correcta de `ResourceNotFoundException`

### 2.3 Bug: Búsqueda de Gastos No Encuentra por Nombre de Usuario

**Problema**: La búsqueda paginada de gastos solo buscaba en `concept` y `note`, ignorando el nombre del usuario asociado.

**Archivo Modificado**: `backend/src/main/java/io/sunbit/app/dao/ExpenseSpecifications.java`

**Solución**:
```java
/**
 * Search in concept, note, or user name/surname fields (case insensitive)
 */
public static Specification<Expense> searchInConceptOrNote(String search) {
    return (root, query, cb) -> {
        if (search == null || search.isEmpty()) {
            return cb.conjunction();
        }
        String lowerSearch = "%" + search.toLowerCase() + "%";
        return cb.or(
            cb.like(cb.lower(root.get("concept")), lowerSearch),
            cb.like(cb.lower(cb.coalesce(root.get("note"), "")), lowerSearch),
            cb.like(cb.lower(root.get("expenseUser").get("name")), lowerSearch),
            cb.like(cb.lower(root.get("expenseUser").get("surname")), lowerSearch),
            cb.like(cb.lower(root.get("expenseUser").get("email")), lowerSearch)
        );
    };
}
```

**Campos de Búsqueda Ampliados**:
- `concept` (original)
- `note` (original)
- `expenseUser.name` (nuevo)
- `expenseUser.surname` (nuevo)
- `expenseUser.email` (nuevo)

### 2.4 Bug: NPE al Editar Usuario sin Enviar Password

**Problema**: Al editar un usuario desde el frontend sin incluir el campo `password` en el JSON, se producía un NullPointerException.

**Archivo Modificado**: `backend/src/main/java/io/sunbit/app/dto/ExpenseUserDto.java`

**Solución**:
```java
@JsonProperty(access = JsonProperty.Access.WRITE_ONLY)
private String password = ""; // Default empty to avoid NPE when field is omitted
```

**Explicación**: Con `@JsonProperty(Access.WRITE_ONLY)`, el campo password no se serializa en respuestas pero sí se deserializa en requests. Sin embargo, si el campo no viene en el JSON, Jackson lo deja como `null`. El default vacío previene NPE en validaciones posteriores.

### 3.3 Contexto de Tema

**Archivo Creado**: `frontend/src/contexts/ThemeContext.jsx`

```jsx
import { createContext, useContext, useState, useEffect } from 'react';

const ThemeContext = createContext(undefined);

function getSystemTheme() {
  return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function ThemeProvider({ children }) {
  const [theme, setThemeState] = useState(() => {
    const stored = localStorage.getItem('theme');
    if (stored && ['light', 'dark', 'system'].includes(stored)) {
      return stored;
    }
    return 'light';
  });

  const resolvedTheme = theme === 'system' ? getSystemTheme() : theme;

  useEffect(() => {
    const html = document.documentElement;
    const body = document.body;
    
    if (resolvedTheme === 'dark') {
      html.classList.add('dark');
      body.classList.add('dark');
      html.style.colorScheme = 'dark';
    } else {
      html.classList.remove('dark');
      body.classList.remove('dark');
      html.style.colorScheme = 'light';
    }
    
    localStorage.setItem('theme', theme);
  }, [theme, resolvedTheme]);

  useEffect(() => {
    if (theme !== 'system') return;
    
    const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');
    const handleChange = () => setThemeState(prev => prev);
    
    mediaQuery.addEventListener('change', handleChange);
    return () => mediaQuery.removeEventListener('change', handleChange);
  }, [theme]);

  const setTheme = (newTheme) => setThemeState(newTheme);

  const toggleTheme = () => {
    setThemeState(prev => {
      if (prev === 'system') {
        return getSystemTheme() === 'dark' ? 'light' : 'dark';
      }
      return prev === 'light' ? 'dark' : 'light';
    });
  };

  return (
    <ThemeContext.Provider value={{ 
      theme, 
      resolvedTheme, 
      setTheme, 
      toggleTheme, 
      isDark: resolvedTheme === 'dark' 
    }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (context === undefined) {
    throw new Error('useTheme must be used within a ThemeProvider');
  }
  return context;
}
```

**Características**:
- **Persistencia**: Guarda preferencia en `localStorage` key `'theme'`
- **Valores soportados**: `'light'`, `'dark'`, `'system'`
- **Detección automática**: Escucha cambios en `prefers-color-scheme` del sistema
- **API expuesta**: `theme`, `resolvedTheme`, `setTheme()`, `toggleTheme()`, `isDark`

## 4. Implementación de Items por Página

### 4.1 Hook Personalizado

**Archivo Creado**: `frontend/src/hooks/useItemsPerPage.js`

```javascript
import { useState, useEffect } from 'react';

/**
 * Hook to get and subscribe to items per page preference from localStorage
 */
export function useItemsPerPage(defaultValue = 10) {
  const [itemsPerPage, setItemsPerPage] = useState(() => {
    const stored = localStorage.getItem('itemsPerPage');
    return stored ? parseInt(stored, 10) : defaultValue;
  });

  useEffect(() => {
    const handleChange = (event) => {
      setItemsPerPage(event.detail);
    };

    window.addEventListener('itemsPerPageChanged', handleChange);
    return () => window.removeEventListener('itemsPerPageChanged', handleChange);
  }, []);

  return itemsPerPage;
}
```

**Características**:
- Sincronización entre pestañas/componentes via `CustomEvent`
- Valor por defecto configurable
- Persistencia en `localStorage`

## 5. Problemas Encontrados y Soluciones

### 5.1 Problema: Modo Oscuro No Se Aplicaba

**Síntoma**: Al seleccionar "Oscuro" en configuración, la página permanecía clara.

**Intentos Fallidos**:
1. Usar `body.dark` como selector CSS
2. Usar `@apply dark:bg-slate-900` en CSS

**Causa Raíz**: Tailwind aplica la clase `dark` en `<html>`, no en `<body>`. El selector CSS necesitaba usar `html.dark body` para mayor especificidad.

**Solución Final**:
```css
/* NO funciona */
body.dark {
  background: ... !important;
}

/* SÍ funciona */
html.dark body {
  background: ...;
}
```

### 5.2 Problema: Error de Función Duplicada

**Síntoma**: Error de Vite: `Identifier 'useTheme' has already been declared`

**Causa**: Durante iteraciones de debugging, se duplicó accidentalmente la función `useTheme()` en ThemeContext.jsx.

**Solución**: Eliminar la declaración duplicada.

### 5.3 Problema: Conflicto de Keys en localStorage

**Síntoma**: Tema no persistía correctamente entre recargas.

**Causa**: En una versión inicial se usaba `'themePreference'` y luego se cambió a `'theme'`, causando inconsistencia.

**Solución**: Unificar a usar solo `'theme'` como key.
