## 5. Implementación del Rol MANAGER

### 5.1 Descubrimiento del Problema

Al intentar probar diferentes roles, se descubrió que **ROLE_MANAGER no estaba implementado**:

```java
// Antes: Solo existían permisos para ADMIN y USER
@PreAuthorize("hasRole('ROLE_ADMIN')")  // Empleados
@PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_USER')")  // Gastos
```

Los usuarios con roleId=3 (MANAGER) recibían error 403 en casi todas las operaciones.

### 5.2 Decisión de Permisos para MANAGER

Se decidió implementar **"Opción A: Gestión de Equipo"**:

| Módulo | Permisos MANAGER |
|--------|-----------------|
| **Employees** | ✅ CRUD completo |
| **Positions** | ❌ Sin acceso |
| **Expenses** | ⚠️ Solo propios |
| **Payrolls** | ✅ Ver todas (sin CRUD) |
| **Users** | ❌ Sin acceso |

### 5.3 Cambios en Backend

#### 5.3.1 EmployeeControllerImpl.java

**Archivo**: `backend/src/main/java/io/sunbit/app/controller/EmployeeControllerImpl.java`

**Cambios**: Agregado ROLE_MANAGER a todas las operaciones CRUD

```java
// ANTES
@PreAuthorize("hasRole('ROLE_ADMIN')")
@GetMapping
public ResponseEntity<?> getAllEmployee()

// DESPUÉS
@PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_MANAGER')")
@GetMapping
public ResponseEntity<?> getAllEmployee()
```

**Métodos modificados**:
- `getAllEmployee()` - listar
- `getEmployeeById()` - ver detalle
- `saveEmployee()` - crear
- `deleteEmployee()` - eliminar
- `updateEmployee()` - actualizar
- `getEmployeeByNameAndSurname()` - buscar

#### 5.3.2 PayrollControllerImpl.java

**Archivo**: `backend/src/main/java/io/sunbit/app/controller/PayrollControllerImpl.java`

**Cambios**: MANAGER puede VER todas las nóminas pero NO crear/editar/eliminar

```java
// Ver todas las nóminas - MANAGER incluido
@PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_MANAGER')")
@GetMapping
public ResponseEntity<?> getAllPayroll()

// Crear/Editar/Eliminar - Solo ADMIN
@PreAuthorize("hasRole('ROLE_ADMIN')")
@PostMapping("/")
public ResponseEntity<?> savePayroll(...)
```

#### 5.3.3 ExpenseControllerImpl.java

**Archivo**: `backend/src/main/java/io/sunbit/app/controller/ExpenseControllerImpl.java`

**Cambios**: MANAGER puede gestionar sus propios gastos (igual que USER)

```java
// ANTES
@PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_USER')")

// DESPUÉS  
@PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_MANAGER','ROLE_USER')")
```

### 5.4 Cambios en Frontend

#### 5.4.1 Layout.jsx

**Archivo**: `frontend/src/components/Layout.jsx`

**Cambios**: Mostrar menú "Empleados" para MANAGER

```jsx
// ANTES
const isAdmin = user?.roleId === 1;

// DESPUÉS
const isAdmin = user?.roleId === 1;
const isManager = user?.roleId === 3;
const isAdminOrManager = isAdmin || isManager;

// Menú lateral
...(isAdmin ? [
  { icon: Briefcase, label: 'Cargos', path: '/positions' },
] : []),
...(isAdminOrManager ? [
  { icon: Users, label: 'Empleados', path: '/employees' },
] : []),
...(isAdmin ? [
  { icon: UserCog, label: 'Usuarios', path: '/users' },
] : []),
```

#### 5.4.2 EmployeesPage.jsx

**Archivo**: `frontend/src/pages/EmployeesPage.jsx`

**Cambios**: Permitir acceso a MANAGER

```jsx
// ANTES
if (!isAdmin) return <AccessDenied />

// DESPUÉS
const canManageEmployees = isAdmin || isManager;
if (!canManageEmployees) return <AccessDenied />
```

#### 5.4.3 PayrollPage.jsx

**Archivo**: `frontend/src/pages/PayrollPage.jsx`

**Cambios**: MANAGER puede ver todas las nóminas pero no tiene botones CRUD

```jsx
// Toggle "Ver todas" disponible para ADMIN y MANAGER
const canViewAll = isAdmin || isManager;

{canViewAll && (
  <button onClick={() => setViewMode(...)}>
    {viewMode === 'mine' ? 'Ver todas' : 'Mis nóminas'}
  </button>
)}

// Botones de crear/editar/eliminar solo para ADMIN
{isAdmin && (
  <button onClick={openCreateModal}>Nueva Nómina</button>
)}
```
