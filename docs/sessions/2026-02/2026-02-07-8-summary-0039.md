## 3. Problemas Encontrados y Soluciones

### 3.1 Problema: Backend sin el nuevo endpoint

**Síntoma**: Página de Gastos en blanco

**Causa**: El contenedor Docker tenía el JAR antiguo sin el endpoint `/search`

**Solución**:
```bash
make build-backend
docker-compose --profile dev restart backend-dev
```

### 3.2 Problema: Error JPQL `grossSalary` no existe

**Síntoma**: Error al compilar
```
could not resolve attribute 'grossSalary' of 'io.sunbit.app.entity.Payroll'
```

**Causa**: El atributo en la entidad Payroll se llama `amount`, no `grossSalary`

**Solución**: Cambiar en `IPayrollDao.java`:
```java
// Antes
"(:minAmount IS NULL OR p.grossSalary >= :minAmount)"
// Después  
"(:minAmount IS NULL OR p.amount >= :minAmount)"
```

### 3.3 Problema: Error PostgreSQL con parámetros null

**Síntoma**: Error 500 al cargar gastos
```
ERROR: could not determine data type of parameter $10
```

**Causa**: PostgreSQL no puede inferir el tipo de un parámetro cuando es `null`. La query JPQL original:
```java
@Query("SELECT e FROM Expense e WHERE " +
       "(:startDate IS NULL OR e.expenseDate >= :startDate)")
```

Cuando `startDate` es null, PostgreSQL no sabe si es `timestamp`, `date`, `varchar`, etc.

**Solución**: Usar **JPA Specifications** en lugar de JPQL estático.

### 3.4 Problema: Contenedor Docker huérfano

**Síntoma**: Contenedor con nombre con hash prefijo
```
59fc0a6c6459_erp-dev-db-container
```

**Solución**:
```bash
docker-compose --profile dev down --remove-orphans
docker-compose --profile dev up -d
```

### 3.5 Problema: React hooks error

**Síntoma**: Error en consola
```
Rendered more hooks than during the previous render
```

**Causa**: El hook `useMemo` estaba DESPUÉS de un `return` condicional:
```jsx
// MAL - hooks después de return condicional
if (isLoading) return <Loading />;
const groupedExpenses = useMemo(() => {...}, [expenses]);
```

**Solución**: Mover todos los hooks ANTES de cualquier return:
```jsx
// BIEN - hooks antes de returns
const groupedExpenses = useMemo(() => {...}, [expenses]);
if (isLoading) return <Loading />;
```

### 3.6 Problema: Error ContainerConfig de Docker Compose

**Síntoma**: 
```
KeyError: 'ContainerConfig'
```

**Causa**: Inconsistencia entre versión de docker-compose y metadatos de contenedores

**Solución**: Limpiar completamente y recrear:
```bash
docker-compose --profile dev down --remove-orphans
docker-compose --profile dev up -d
```

## 4. Solución Final: JPA Specifications

### 4.1 Archivos Creados

**`backend/src/main/java/io/sunbit/app/dao/ExpenseSpecifications.java`**
```java
package io.sunbit.app.dao;

import java.time.LocalDateTime;
import org.springframework.data.jpa.domain.Specification;
import io.sunbit.app.entity.Expense;

public class ExpenseSpecifications {

    public static Specification<Expense> hasUserId(Long userId) {
        return (root, query, cb) -> {
            if (userId == null) {
                return cb.conjunction(); // Sin filtro
            }
            return cb.equal(root.get("expenseUser").get("id"), userId);
        };
    }

    public static Specification<Expense> searchInConceptOrNote(String search) {
        return (root, query, cb) -> {
            if (search == null || search.isEmpty()) {
                return cb.conjunction();
            }
            String lowerSearch = "%" + search.toLowerCase() + "%";
            return cb.or(
                cb.like(cb.lower(root.get("concept")), lowerSearch),
                cb.like(cb.lower(cb.coalesce(root.get("note"), "")), lowerSearch)
            );
        };
    }

    public static Specification<Expense> hasMinAmount(Double minAmount) {
        return (root, query, cb) -> {
            if (minAmount == null) return cb.conjunction();
            return cb.greaterThanOrEqualTo(root.get("amount"), minAmount);
        };
    }

    public static Specification<Expense> hasMaxAmount(Double maxAmount) {
        return (root, query, cb) -> {
            if (maxAmount == null) return cb.conjunction();
            return cb.lessThanOrEqualTo(root.get("amount"), maxAmount);
        };
    }

    public static Specification<Expense> hasStartDate(LocalDateTime startDate) {
        return (root, query, cb) -> {
            if (startDate == null) return cb.conjunction();
            return cb.greaterThanOrEqualTo(root.get("expenseDate"), startDate);
        };
    }

    public static Specification<Expense> hasEndDate(LocalDateTime endDate) {
        return (root, query, cb) -> {
            if (endDate == null) return cb.conjunction();
            return cb.lessThanOrEqualTo(root.get("expenseDate"), endDate);
        };
    }

    public static Specification<Expense> withFilters(
            Long userId, String search, 
            Double minAmount, Double maxAmount,
            LocalDateTime startDate, LocalDateTime endDate) {
        return Specification.where(hasUserId(userId))
                .and(searchInConceptOrNote(search))
                .and(hasMinAmount(minAmount))
                .and(hasMaxAmount(maxAmount))
                .and(hasStartDate(startDate))
                .and(hasEndDate(endDate));
    }
}
```

### 4.2 Modificaciones en Servicios

**`ExpenseServiceImpl.java`**
```java
@Override
public Page<Expense> findWithFilters(ExpenseSearchCriteria criteria, 
        Pageable pageable, String headerAuth) throws Exception {
    // ... validación de token y permisos ...
    
    // Usar Specifications en lugar de JPQL
    Page<Expense> expenses = expenseDao.findAll(
        ExpenseSpecifications.withFilters(
            effectiveUserId,
            criteria.getSearch(),
            criteria.getMinAmount(),
            criteria.getMaxAmount(),
            startDate,
            endDate
        ),
        pageable
    );
    
    expenses.forEach(this::loadExpenseUser);
    return expenses;
}
```

### 4.3 Por qué Specifications resuelve el problema

El patrón Specification construye la query **dinámicamente**:
- Si un parámetro es `null`, simplemente **no añade esa condición** a la query
- No envía parámetros null a PostgreSQL
- Cada Specification retorna `cb.conjunction()` (equivalente a `1=1`) cuando no hay filtro

## 7. Lecciones Aprendidas

### 7.1 PostgreSQL y Parámetros Null en JPQL

**Problema**: PostgreSQL requiere conocer el tipo de todos los parámetros, incluso si son null.

**Aprendizaje**: Para queries con filtros opcionales, usar:
- **JPA Specifications** (recomendado) - construye queries dinámicamente
- **Native queries con COALESCE** - requiere casting explícito
- **Criteria API** - similar a Specifications pero más verboso

### 7.2 React Hooks y Returns Condicionales

**Regla de Hooks**: Los hooks deben ejecutarse en el **mismo orden** en cada render.

```jsx
// ❌ MAL - hooks después de return
if (loading) return <Spinner />;
const data = useMemo(() => process(items), [items]);

// ✅ BIEN - hooks antes de cualquier return
const data = useMemo(() => process(items), [items]);
if (loading) return <Spinner />;
```

### 7.3 Docker Compose y Contenedores Inconsistentes

Cuando hay errores de estado de contenedores (`ContainerConfig`, orphans):
```bash
docker-compose --profile <profile> down --remove-orphans
docker-compose --profile <profile> up -d
```
