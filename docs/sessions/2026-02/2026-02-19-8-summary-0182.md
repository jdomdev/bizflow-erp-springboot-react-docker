### 2. Creación de docs/guide/SETUP_CREDENTIALS.md

Nuevo archivo de documentación completo para la configuración de credenciales.

#### Contenido del archivo:

**Estructura requerida:**
```
scripts/secrets/
└── users_with_passwords/
    ├── dev_users.json
    ├── test_users.json
    └── prod_users.json
```

**Pasos de configuración:**
1. Crear el directorio de secrets
2. Copiar las plantillas desde `scripts/seeds/data/*/users.json.example`
3. Generar contraseñas reemplazando `<SEED_PASSWORD_PLACEHOLDER>`

**Formato recomendado de contraseñas:**
- Mínimo 8 caracteres
- Al menos una letra mayúscula
- Al menos una letra minúscula
- Al menos un número
- Al menos un carácter especial (@, #, $, %, &, *, !)

**Comando de generación automática:**
```bash
openssl rand -base64 12 | tr -d '\n' | head -c 12
```

**Script de ayuda compatible macOS/Linux:**
```bash
sed -i.bak 's/<SEED_PASSWORD_PLACEHOLDER>/TU_PASSWORD_TEMPORAL/g' scripts/secrets/users_with_passwords/dev_users.json
```

**Usuarios predeterminados por rol:**
| Rol | Ejemplo de email | Descripción |
|-----|------------------|-------------|
| ADMIN | ada.lovelace@bizflowerp.com | Acceso completo al sistema |
| MANAGER | nikola.tesla@bizflowerp.com | Gestión de empleados y recursos |
| USER | ken.thompson@bizflowerp.com | Usuario estándar |

**Advertencias de seguridad para producción:**
- NUNCA usar las mismas contraseñas que en desarrollo
- Generar contraseñas únicas y seguras para cada usuario
- Almacenar las contraseñas en un gestor de contraseñas seguro
- Considerar usar HashiCorp Vault, AWS Secrets Manager, etc.

### 3. Resolución de Problemas con GitGuardian

#### Problema inicial:
GitGuardian detectaba "secretos" en el archivo `SETUP_CREDENTIALS.md` debido a ejemplos de contraseñas:
- `TempPass123!`
- `TuContraseñaSegura123!`
- `OtraContraseñaSegura456@`
- `aBcD1234!@#$`

#### Solución aplicada:
Se reemplazaron todos los ejemplos por placeholders obvios:
- `<TU_PASSWORD_SEGURA>`
- `<OTRA_PASSWORD_SEGURA>`
- `TU_PASSWORD_TEMPORAL`
- `(cadena aleatoria de 12 caracteres)`

#### Problema persistente:
GitGuardian analiza TODO el historial de commits de la PR, no solo el estado final.

#### Solución final:
Squash de todos los commits en uno solo limpio:

```bash
git reset --soft origin/dev
git commit -m "docs: improve README with features, environments, credentials guide and Windows support"
git push --force origin feat/prod-environment-docs
```

Resultado: PR con un solo commit (`4b49561`) sin historial de contraseñas de ejemplo.

## Notas Técnicas

### Compatibilidad sed macOS/Linux
En macOS, `sed -i` requiere una extensión de backup obligatoria. La solución compatible es usar `sed -i.bak` que funciona en ambos sistemas:

```bash
# Funciona en Linux y macOS
sed -i.bak 's/old/new/g' archivo.txt
rm -f archivo.txt.bak  # Opcional: eliminar backup
```

### Proxy Vite
La configuración en `vite.config.js` redirige `/api` al backend:

```javascript
proxy: {
  '/api': {
    target: process.env.VITE_API_URL || 'http://localhost:8082',
    changeOrigin: true,
  },
}
```

### WSL2 para Windows
El proyecto requiere WSL2 en Windows porque:
- `make` no funciona en Windows nativo
- Docker Desktop funciona mejor con WSL2
- Los scripts bash no funcionan en PowerShell
- Evita mantener dos sets de comandos
