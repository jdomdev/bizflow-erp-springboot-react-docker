## 5. Mejora: Usuario Creador en Gastos

### 5.1 Problema Identificado

Los gastos en el Dashboard y ExpenseList no mostraban quién los había creado, dificultando la trazabilidad.

### 5.2 Solución Backend

**Archivo modificado**: `backend/src/main/java/io/sunbit/app/entity/Expense.java`

```java
@JsonGetter("expenseUserName")
public String getExpenseUserName() {
    if (expenseUser == null) return null;
    String name = expenseUser.getName();
    String surname = expenseUser.getSurname();
    if (name == null && surname == null) return null;
    return ((name != null ? name : "") + " " + (surname != null ? surname : "")).trim();
}

@JsonGetter("expenseUserEmail")
public String getExpenseUserEmail() {
    return expenseUser != null ? expenseUser.getEmail() : null;
}
```

## 8. Mejora: Columna ID Visible

### 8.1 Decisión de Diseño

Se decidió mostrar el ID de cada registro en las tablas de Usuarios y Empleados por las siguientes razones:

- Útil para soporte técnico y debugging
- Permite referencia rápida ("el usuario 45 tiene un problema")
- Común en sistemas ERP/administrativos

### 8.2 Implementación

- **Posición**: Primera columna de la tabla
- **Estilo**: Texto gris discreto (`text-gray-400`), fuente monoespaciada (`font-mono`)
- **Ancho**: Fijo (`w-16`)

## 16. Lecciones Aprendidas

### 16.1 Contraste de Colores

Siempre verificar el contraste cuando se usan fondos de colores claros. El texto blanco sobre verde claro no es legible.

### 16.2 Nomenclatura de Columnas

Los nombres de columnas deben ser explícitos sobre lo que muestran. "Vínculo" es ambiguo; "Empleado" y "Usuario" son claros.

### 16.3 IDs en Tablas Administrativas

En sistemas ERP, mostrar el ID es útil para administradores y soporte técnico, aunque debe ser discreto para no sobrecargar la interfaz.

### 16.4 Getters JSON en Entidades JPA

Los `@JsonGetter` son una forma limpia de exponer datos calculados o de relaciones sin modificar la estructura de la entidad.
