# Session Summary: Backend, Docker and CRUD (up to 2025-12-01)

## 1. Objetivo General

El objetivo principal de esta fase ha sido asegurar el correcto funcionamiento del backend Java Spring Boot y su integración con Docker y PostgreSQL, así como la robustez de los endpoints CRUD para empleados y gastos, y la correcta serialización de usuarios y roles.

## 2. Contexto y Estructura del Proyecto

- **Backend:** Java Spring Boot, Spring Security, JWT, Hibernate/JPA.
- **Frontend:** React (Vite, Tailwind), no modificado en esta fase.
- **Base de datos:** PostgreSQL en contenedor Docker.
- **Orquestación:** docker-compose para backend y base de datos.
- **Persistencia:** Volúmenes Docker para la BDD.

## 3. Problemas Abordados y Soluciones

### 3.1. Duplicidad de Imágenes Docker
- Se detectó que el backend generaba imágenes duplicadas por falta de nombre explícito en `docker-compose.yml`.
- **Solución:** Se añadió la clave `image:` para el backend, asegurando que siempre se use la misma imagen y evitando duplicados.

### 3.2. Errores de Serialización (Bucle Infinito)
- El endpoint GET ALL user devolvía un error de recursión infinita por relaciones bidireccionales entre `ExpenseUser` y `Role`.
- **Solución:** Se añadieron las anotaciones `@JsonManagedReference` y `@JsonBackReference` en las entidades correspondientes.
- Se revisaron los DTOs y mappers para asegurar que no se generen ciclos al serializar.

### 3.3. Esquema de Base de Datos Incompleto
- Tras reiniciar los contenedores, la tabla `expense_user` no tenía la columna `employee_id`, causando errores 400/500 en el registro de usuarios.
- **Solución:** Se verificó que `spring.jpa.hibernate.ddl-auto=update` estuviera activo y se reinició el backend para forzar la actualización del esquema.

### 3.4. CRUD de Empleados y Gastos
- Se revisaron los endpoints y la persistencia de datos en la BDD.
- Se comprobó el correcto funcionamiento de los métodos de alta, edición, borrado y listado.

## 4. Proceso de Limpieza y Reconstrucción
