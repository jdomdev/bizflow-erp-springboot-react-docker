# Extended Daily Summary - 2025-12-07

## 1. Contexto y Objetivo
En la jornada del 7 de diciembre de 2025, el objetivo principal fue eliminar completamente el campo `username` del sistema ERP (Spring Boot + React + Docker), migrando a un modelo donde la identificación de usuario se realiza únicamente por `email`, y opcionalmente `name` y `surname`. Esto incluyó backend, frontend, scripts, migraciones SQL y toda la documentación.

## 2. Problemas Detectados
- **Errores de registro:** El backend arrojaba errores 400 por campos requeridos y problemas de base de datos relacionados con la columna `username` y referencias a `employee_id`.
- **Inconsistencias en el modelo:** Existían referencias a `username` en entidades, DTOs, controladores, scripts y documentación, lo que generaba confusión y errores en el flujo de registro y autenticación.
- **Desalineación entre modelo Java y base de datos:** El modelo `ExpenseUser` y la tabla `expense_user` no estaban sincronizados, especialmente en la gestión de relaciones con empleados.

## 3. Decisiones y Razonamiento
- **Eliminar `username` en todos los niveles:** Se optó por una migración total para evitar ambigüedades y simplificar la lógica de autenticación y registro.
- **Usar `email` como identificador único:** Es el estándar moderno y facilita la integración con otros sistemas y la experiencia de usuario.
- **Actualizar documentación y ejemplos:** Para evitar confusiones futuras, se revisaron y actualizaron todos los ejemplos, scripts y markdowns.
- **Alinear modelo de datos y código:** Se ajustaron las migraciones SQL y el modelo Java para reflejar la nueva estructura.
