## 3. Problema de Seguridad Identificado: Nóminas

### 3.1 Descripción del Problema

Al acceder con un usuario normal (ej: Nikola Tesla), la página de nóminas mostraba **todas las nóminas del sistema** (305 registros), cuando solo debería mostrar las propias.

### 3.2 Análisis Técnico

#### Endpoints Actuales del Backend
```java
GET /payroll/                    → @PreAuthorize("hasRole('ROLE_ADMIN')")
GET /payroll/employee/{id}       → @PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_USER')")
GET /payroll/user/{expenseUserId} → @PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_USER')")
```

#### Problema en el Frontend
El código verificaba `roleIds?.includes(2)` pensando que `2 = ADMIN`, pero en realidad:
- `roleId = 1` → ADMIN
- `roleId = 2` → USER
- `roleId = 3` → MANAGER

#### Problema en los Datos
```sql
SELECT employee_id IS NOT NULL as has_employee, 
       expense_user_id IS NOT NULL as has_user, 
       COUNT(*) FROM payroll GROUP BY 1, 2;

-- Resultado:
-- has_employee | has_user | count
-- t            | f        | 305
```

Las 305 nóminas tienen `employee_id` pero **ninguna** tiene `expense_user_id`, por lo que el endpoint `/payroll/user/{id}` siempre devuelve vacío.

## 5. Solución Arquitectónica Propuesta

### 5.1 Nuevo Endpoint: `/payroll/my`

```java
@GetMapping("/my")
@PreAuthorize("hasAnyRole('ROLE_ADMIN','ROLE_USER','ROLE_MANAGER')")
public ResponseEntity<?> getMyPayrolls(@AuthenticationPrincipal UserDetails userDetails) {
    // 1. Obtiene userId del token JWT
    // 2. Busca nóminas por expense_user_id
    // 3. Si el usuario tiene employee asociado, también busca por employee_id
    // 4. Une ambos resultados (sin duplicados)
    return payrollService.findAllByCurrentUser(userId);
}
```

#### Ventajas
- ✅ Un solo endpoint, lógica en backend
- ✅ Seguro: usuario solo ve sus propias nóminas
- ✅ Frontend simple: solo llama a `/payroll/my`
- ✅ Soporta ambos casos (empleado Y freelance)

### 5.2 Vinculación Automática Employee ↔ ExpenseUser

Cuando se crea un empleado o usuario, vincular automáticamente si coincide el email:

```java
// EmployeeServiceImpl.save()
@Transactional
public Employee save(Employee employee) {
    Employee saved = employeeDao.save(employee);
    
    // Buscar si existe usuario con mismo email
    Optional<ExpenseUser> user = userDao.findByEmail(employee.getEmail());
    if (user.isPresent() && user.get().getEmployee() == null) {
        user.get().setEmployee(saved);
        userDao.save(user.get());
    }
    
    return saved;
}

// ExpenseUserServiceImpl.save()
@Transactional  
public ExpenseUser save(ExpenseUser user) {
    // Buscar si existe empleado con mismo email
    Optional<Employee> employee = employeeDao.findByEmail(user.getEmail());
    if (employee.isPresent()) {
        user.setEmployee(employee.get());
    }
    
    return userDao.save(user);
}
```

### 5.3 Opciones Alternativas Consideradas

| Opción | Descripción | Decisión |
|--------|-------------|----------|
| Triggers PostgreSQL | Vincular automáticamente a nivel de BD | ❌ Menos debuggeable |
| Dos llamadas frontend | Llamar a `/user/{id}` y `/employee/{id}` | ❌ Lógica en frontend |
| Query params `/search` | Endpoint flexible | ❌ Menos seguro |
