## 🐳 Aclaración sobre Docker vs Local

### Estado Actual de los Contenedores Docker

Los **tres entornos** Docker están levantados simultáneamente:

| Entorno | Frontend | Backend | Base de Datos |
|---------|----------|---------|---------------|
| **PROD** | :8080 | :8181 | :5442 |
| **DEV** | :8085 | :8082 | :5433 |
| **TEST** | :8086 | :8083 | :5434 |

### ¿Dónde se ejecutó http://localhost:3000?

El servidor en el puerto **3000** era el servidor de desarrollo de **Vite ejecutándose en LOCAL**, **NO en Docker**.

**Explicación:**
- Cuando ejecutamos `npm run dev` en el directorio `frontend/`, Vite inicia un servidor de desarrollo local en el puerto 3000
- Este servidor:
  - Lee los archivos fuente directamente del sistema de archivos local
  - Proporciona Hot Module Replacement (HMR) para ver cambios instantáneos
  - **NO está dentro de ningún contenedor Docker**
- Los contenedores Docker frontend sirven la aplicación **compilada** (dist/) via Nginx en los puertos 8080/8085/8086

### Diferencia Práctica

| Aspecto | Vite Local (:3000) | Docker Frontend (:8085) |
|---------|-------------------|------------------------|
| Código servido | Fuente (src/) | Compilado (dist/) |
| Hot reload | ✅ Sí | ❌ No |
| Cambios visibles | Instantáneos | Requiere rebuild |
| Uso típico | Desarrollo activo | Testing/Producción |
| Backend conectado | Ninguno (sin .env) | DEV (:8082) |

### Para ver los cambios en Docker

Para que los cambios de hoy se reflejen en los contenedores Docker, necesitarías:

```bash
# Reconstruir y reiniciar el contenedor de desarrollo
make frontend-dev-rebuild
# o
docker-compose -f docker-compose.dev.yml up --build -d frontend
```
