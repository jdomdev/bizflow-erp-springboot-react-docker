## 3. Fase 2: Configuración Multi-Entorno de Vite

### 3.1 Problema Identificado

El archivo `frontend/vite.config.js` tenía el proxy del backend hardcodeado:

```javascript
// Antes - solo funcionaba para DEV
proxy: {
  '/api': {
    target: 'http://localhost:8082',  // Puerto DEV fijo
    ...
  }
}
```

### 3.2 Solución Implementada

Se configuró el proxy para usar variable de entorno:

#### `frontend/vite.config.js`
```javascript
proxy: {
  '/api': {
    target: process.env.VITE_API_URL || 'http://localhost:8082',
    changeOrigin: true,
    secure: false
  }
}
```

#### `frontend/package.json`
```json
{
  "scripts": {
    "dev": "vite",
    "dev:test": "VITE_API_URL=http://localhost:8083 vite",
    "dev:prod": "VITE_API_URL=http://localhost:8181 vite"
  }
}
```

### 3.3 Mapeo de Puertos por Entorno

| Entorno | Puerto Backend | Comando npm |
|---------|----------------|-------------|
| DEV | 8082 | `npm run dev` |
| TEST | 8083 | `npm run dev:test` |
| PROD | 8181 | `npm run dev:prod` |

### 3.4 Estrategia de Uso

**Importante**: Solo DEV usa Vite local para desarrollo. TEST y PROD usan el frontend containerizado en Docker.

```bash
# Desarrollo local (DEV)
cd frontend
npm run dev
# → Vite en localhost:5173 → proxy a backend:8082

# Para TEST/PROD se usa Docker
```

## 5. Fase 4: Corrección de Validaciones de Employee

### 5.1 Problema Identificado

La entidad `Employee.java` tenía validaciones muy restrictivas:

```java
@Length(min = 3, max = 128)  // name - mínimo 3 caracteres
private String name;

@Length(min = 5, max = 255)  // surname - mínimo 5 caracteres  
private String surname;
```

### 5.2 Employees que Fallaban

#### Nombres muy cortos (< 3 chars)
```
mo.farah@bizflowerp.com: name='Mo' (2 chars)
ai.weiwei@bizflowerp.com: name='Ai' (2 chars)
```

#### Apellidos muy cortos (< 5 chars)
```
vint.cerf@bizflowerp.com: surname='Cerf' (4 chars)
brendan.eich@bizflowerp.com: surname='Eich' (4 chars)
larry.wall@bizflowerp.com: surname='Wall' (4 chars)
muhammad.ali@bizflowerp.com: surname='Ali' (3 chars)
ang.lee@bizflowerp.com: surname='Lee' (3 chars)
lao.tse@bizflowerp.com: surname='Tse' (3 chars)
confucio.lu@bizflowerp.com: surname='Lu' (2 chars)
immanuel.kant@bizflowerp.com: surname='Kant' (4 chars)
david.hume@bizflowerp.com: surname='Hume' (4 chars)
johann.bach@bizflowerp.com: surname='Bach' (4 chars)
# ... y 11 más
```

### 5.3 Solución Implementada

Se redujo el mínimo a 2 caracteres para ambos campos:

#### `backend/src/main/java/io/sunbit/app/entity/Employee.java`

```java
// Antes
@Length(min = 3, max = 128)
private String name;
@Length(min = 5, max = 255)
private String surname;

// Después
@Length(min = 2, max = 128)
private String name;
@Length(min = 2, max = 255)
private String surname;
```

### 5.4 Justificación del Cambio

- Nombres asiáticos legítimos: "Ai", "Mo", "Bo"
- Apellidos cortos comunes: "Li", "Wu", "Lu", "Lee", "Ali"
- `min = 2` evita campos vacíos mientras permite nombres reales
- Compatible con datos internacionales

## 9. Problemas Encontrados y Soluciones

### 9.1 Filter-Repo Elimina Remote

**Problema**: Después de ejecutar `git filter-repo`, el remote origin desaparece.

**Solución**: Re-agregar manualmente:
```bash
git remote add origin git@github.com:jdomdev/bizflow-erp-springboot-react-docker.git
```

### 9.2 Volúmenes No Eliminados

**Problema**: Al ejecutar `down --volumes`, a veces los volúmenes persisten.

**Causa**: Interrupción del comando (Ctrl+C) o contenedores aún en uso.

**Solución**: Verificar con `docker volume ls | grep postgres` y usar `--profile {env}` específico.

### 9.3 Validación de Employee Muy Restrictiva

**Problema**: Nombres cortos legítimos (Mo, Ai, Lee, Ali) fallaban con error 400.

**Solución**: Reducir `@Length(min=...)` de 3/5 a 2/2 caracteres.

## 13. Lecciones Aprendidas

### 13.1 Seguridad en Documentación

**Lección**: Los documentos de sesión pueden exponer secretos inadvertidamente. Siempre revisar antes de commitear.

**Acción**: Añadir verificación de patrones sensibles antes de commits de documentación.

### 13.2 Validaciones Internacionales

**Lección**: Las validaciones de longitud mínima deben considerar nombres de diferentes culturas.

**Acción**: Usar `min = 2` como estándar para nombres/apellidos.

### 13.3 Git Filter-Repo

**Lección**: Es una herramienta poderosa pero destructiva. Siempre:
- Backup antes de ejecutar
- Verificar resultado con `git log -p -S "pattern"`
- Restaurar remote después de usar
