### 1.3 Corrección de Visualización de Nombre de Empleado

**Problema:** La función `getEmployeeName` solo buscaba por `employeeId` en el cache, pero para usuarios no-admin el DTO ya incluía `employeeName` y `employeeSurname`.

**Solución:** Refactorizar la función para priorizar datos del DTO:

```jsx
const getEmployeeName = (payroll) => {
  // Primero intentar desde el DTO (para usuarios no-admin)
  if (payroll.employeeName || payroll.employeeSurname) {
    return `${payroll.employeeName || ''} ${payroll.employeeSurname || ''}`.trim();
  }
  // Fallback al cache de empleados (para admin)
  const employee = employees.find(e => e.id === payroll.employeeId);
  return employee ? `${employee.name} ${employee.surname}` : 'Empleado no encontrado';
};
```

## 5. Corrección de Formato de Fecha en ExpenseList

### Problema Identificado

Las fechas aparecían como "Invalid date" en la lista de gastos.

### Causa Raíz

El backend de Java envía `LocalDateTime` como array: `[year, month, day, hour, minute, second, nano]`, pero el frontend esperaba un string ISO.

### Solución Implementada

Función `formatDate` mejorada en `ExpenseList.jsx`:

```jsx
const formatDate = (dateString) => {
  if (!dateString) return 'Fecha no disponible';
  
  try {
    // Handle array format from Java LocalDateTime
    if (Array.isArray(dateString)) {
      const [year, month, day, hour = 0, minute = 0] = dateString;
      const date = new Date(year, month - 1, day, hour, minute);
      return date.toLocaleString('es-ES', {
        year: 'numeric',
        month: 'short',
        day: 'numeric',
        hour: '2-digit',
        minute: '2-digit'
      });
    }
    
    // Handle ISO string or other formats
    const date = new Date(dateString);
    if (isNaN(date.getTime())) {
      return 'Fecha no válida';
    }
    return date.toLocaleString('es-ES', { /* options */ });
  } catch {
    return 'Fecha no válida';
  }
};
```

### 6.2 AuthenticationController.java

Se modificó el endpoint de login para extraer y enviar datos completos:

```java
@PostMapping("/login")
public ResponseEntity<?> login(@RequestBody @Valid AuthenticationRequest authRequest) {
    try {
        Authentication authentication = authManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                authRequest.getEmail(), authRequest.getPassword()));
        ExpenseUser user = (ExpenseUser) authentication.getPrincipal();
        String accessToken = jwtAuthUtil.generateAccessToken(user);
        
        // Get the first role
        Long roleId = null;
        String roleName = null;
        if (user.getRoles() != null && !user.getRoles().isEmpty()) {
            var firstRole = user.getRoles().iterator().next();
            roleId = firstRole.getId();
            roleName = firstRole.getName();
        }
        
        AuthenticationResponse authzResponse = new AuthenticationResponse(
            user.getId(),
            user.getEmail(), 
            accessToken,
            roleId,
            roleName
        );
        return ResponseEntity.ok(authzResponse);
    } catch (BadCredentialsException ex) {
        return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();
    }
}
```

## 10. Problemas Pendientes

### 10.1 Sesiones Antiguas

Los usuarios con sesiones previas a esta actualización tendrán datos incompletos en localStorage (solo `email`, sin `id` ni `roleId`). 

**Solución temporal:** Se añadió mensaje indicando necesidad de re-login.
**Solución permanente:** Considerar migración automática del store o forzar logout en próxima versión.

### 10.2 Campo de Fecha en Backend

El backend devuelve fechas como arrays Java (`[2026, 1, 20, 9, 0, 0]`) en lugar de ISO strings. Se manejó en frontend, pero idealmente debería normalizarse en el backend con un serializer Jackson.
